# Django Blog Application

Djangoで構築したブログアプリケーション。
ローカルでの機能開発から、AWS EC2環境への本番デプロイ（Gunicorn + Nginx + Let's EncryptによるHTTPS化）までを一気通貫で設計・構築した。

---

##  公開URL
- **本番サイト**: https://my-django-blog-2026.duckdns.org/
- **プロトコル**: HTTPS（SSL/TLS対応）

---

## 主な機能
### ユーザー機能
- **記事一覧表示**: 投稿された記事を一覧で確認
- **記事詳細表示**: 個別の記事本文とアイキャッチ画像の閲覧
- **キーワード検索機能**:
  - タイトルおよび本文を対象とした部分一致検索（Django `Q` オブジェクトを用いたOR検索）
- **いいね機能**:
  - 記事に対するいいねの登録・解除
  - いいね数のカウント表示
  - （いいねした記事の一覧表示）

### 管理者機能
- Django標準の管理画面（Admin）による記事のCRUD操作（作成・編集・削除）

##  インフラ・設計のこだわりと工夫した点

1. **Nginx × Gunicornによる役割分担とパフォーマンス向上**
   - CSSや画像などの静的ファイルは、Djangoを経由させずNginxが直接配信することで、アプリケーションサーバーの負荷を最小限に抑制している。
   - NginxとGunicorn間の通信にはTCPポート（127.0.0.1:8000）ではなく、**UNIXドメインソケット（.sock）**を採用し、同一ホスト内通信の高速化し、内部セキュリティを向上している。

2. **常駐化と耐障害性（systemd)**
   - GunicornをLinuxの `systemd` サービスとしてデーモン化。ターミナル切断後も24時間常駐稼働し、サーバー再起動時にも自動起動（`enable`）する運用体制を構築した。

3. **セキュリティ対応**
   - Certbotを用いてSSL/TLS証明書を導入し、HTTPS暗号化した。
   - 本番環境向けに `settings.py` の `DEBUG = False` を設定し、エラー発生時の機密情報漏洩を防止。
   - `ALLOWED_HOSTS` に自分のドメインおよび固定IPのみを指定し、ホストヘッダー攻撃への耐性を確保。
